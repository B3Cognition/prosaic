# Prosaic Python Parity Implementation Plan

> For agentic workers: execute tasks with independent domain workers and integrate differential tests continuously.

**Goal:** Replace TS Prosaic with a complete Python implementation after parity and consumer validation.

**Architecture:** Separate core discovery/configuration, registry and transformation,
filesystem lifecycle, foreign import, and CLI. Preserve original dictionary contracts.

**Tech Stack:** Python 3.11+, PyYAML with YAML 1.2 scalar resolution, native TOML grammar, pyuca, pytest.

**Spec:** ../../migration.md

## Global Constraints

- Frozen reference 0f7e1878597ef4b52e6be26780c93d2a4db665a4 in `.reference`.
- Python production code must work without Node or the reference checkout.
- CLI remains `prosaic`; all original commands and camelCase serialized keys remain.
- Keep other repositories and existing consumer installations unchanged.
- Use separate domain modules and isolated directories for differential runs.

## Review Focus

- YAML scalar typing and duplicate keys must match js-yaml.
- Generated bytes and no-op behavior must match, including trailing newlines.
- Symlinks and path escapes must preserve filesystem containment.
- Existing manifests and backups must remain usable across implementations.
- Runtime inspection hashes and Harness fingerprints must remain stable.
