# Prosaic 0.5.0 — native output contracts

Prosaic now distributes Claude skills and rules to their native discovery paths,
combines rules in a managed AGENTS.md block, and provides a read-only CI drift
check. Fresh projects default to the native contract. Runtime model execution,
provider configuration and canonical inspection are unchanged.

## Install and select a contract

```sh
uv tool install 'b3-prosaic==0.5.0'
# Or: pipx install 'b3-prosaic==0.5.0'
```

Commit an explicit selection for consistent development and CI:

```yaml
outputContracts: native-v1
targets: [claude-code, agents-md]
```

Existing selector-free configuration and legacy manifests preserve previous
layouts. Native ownership retains the native selection across local runs.
Repositories cloned without config or provenance are treated as fresh; pin
`outputContracts: legacy` if their previous layouts must remain in use.

## Generated output

- Skills: `.claude/skills/<name>/SKILL.md`, with per-skill resources alongside it.
- Rules: `.claude/rules/<name>.md`, preserving Claude `paths` frontmatter.
- Generic rules: one deterministic region in root AGENTS.md, sorted by source ID.
- Existing Claude agent/command paths and all other target descriptors remain.

The generic AGENTS.md text does not implement Claude's path scoping. The
`codex-cli` descriptor is unchanged; Codex can consume the generic AGENTS.md.
These are file-distribution contracts, independent of Runtime's native and
OpenAI-compatible providers.

## Migration and local edits

Preview with `prosaic apply --dry-run`. Native planning checks collisions,
aliases, ownership and hashes before mutation. Legacy outputs are removed only
when recorded, unedited, and after replacements and ownership saves succeed.
Conflicts preserve existing files and abort the run.

AGENTS.md uses `<!-- prosaic:begin -->` and `<!-- prosaic:end -->`. Bytes outside
the owned region survive apply and revert. Block ownership and native target
selection are kept in `.prosaic-blocks.json`, outside the existing whole-file
manifest, so older clients cannot acquire deletion rights over local content.
Keep local prose outside the markers and edit central prose in canonical source.
Malformed, duplicate, edited or unowned markers fail closed.

Partial artifact-type runs preserve stale whole-file entries whose type cannot
be established from legacy provenance; use a full apply for migration cleanup.
To return to legacy output, revert native outputs before selecting legacy.

## CI and verification

`prosaic check [--json]` checks valid source and matching expected output without
locks or writes. Exit 1 indicates errors, drift or conflicts. Matching committed
files can pass without local provenance, but identifying extra stale generated
files requires the ownership manifests; arbitrary handwritten files are not
classified as generated output.

The default registry remains available as the legacy baseline. The native
overlay is versioned `1.1.0-native.1`. New fixture outputs and the contract matrix
are generated by `scripts/generate_contracts.py`; immutable v0.2.0 fixtures and
differential tests remain intact.

Local feature verification passed 780 Python tests and 17 installed-wheel smoke
checks with Node hidden. The release workflow separately qualifies exact
committed artifacts across Linux x64/arm64 and Windows on Python 3.11–3.13,
then promotes the same bytes to PyPI and GitHub with checksums and receipts.

Claude Code 2.1.308 advertised the generated skill during startup. A logged-out
session prevented model invocation, so live rule/resource loading remains an
acceptance limit; filesystem tests are not presented as proof of that behavior.

See [native output contracts](native-output-contracts.md) for the complete
ownership, rollback and CI boundaries.
